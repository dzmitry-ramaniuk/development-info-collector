# Практика ограничений и маршрутизации

## Запуск

Нужны PostgreSQL 16–18 с `psql` и отдельная учебная БД, Python 3 без сторонних библиотек. Из этого каталога:

```bash
psql -X -v ON_ERROR_STOP=1 -d demo -f 01-partition-constraints.sql
python3 02-stable-routing.py
```

SQL создаёт отдельную схему в транзакции, проверяет два направления FK, row-trigger на существующей/будущей партиции и отклонение неверных ссылок. Завершение через ROLLBACK удаляет все учебные объекты. Схема должна отсутствовать до запуска; ошибка о существующем имени намеренно останавливает сценарий.

Python проверяет одинаковый routing в независимых процессах с `PYTHONHASHSEED=1`, `2`, `random`. Изменение числа/порядка shards требует отдельной миграции данных; тест не проверяет реальные соединения.

## Что проверено

15 октября 2026 года SQL прошёл на PostgreSQL 18.6 в отдельном Docker-контейнере; Python-проверка также выполнена. Двухсессионные сценарии row-lock/INSERT, стабильного снимка RR, write skew и SERIALIZABLE с `40001` проверены на том же сервере. Версии PostgreSQL 16–17 в этом запуске не проверялись. Практикум двух сессий находится в [транзакциях](../05-transactions.html); контекст ограничений и routing — в [партиционировании](../09-partitioning-sharding.html).
