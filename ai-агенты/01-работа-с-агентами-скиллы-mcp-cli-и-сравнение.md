## Введение

AI-агент в разработке — это не «магический автокомплит», а исполнитель задач по заданному процессу: он читает контекст, применяет инструкции, использует инструменты (файлы, терминал, внешние источники), затем выдаёт результат.

Ключевая идея: чем лучше вы задали **цель**, **границы** и **критерии приёмки**, тем стабильнее и полезнее результат.

## Как эффективно работать с AI-агентами

### Базовый цикл работы

1. Сформулируйте задачу через результат, а не через абстракцию.
2. Уточните ограничения: стиль кода, формат ответа, какие файлы можно менять.
3. Дайте критерии готовности: тесты, проверки линтером, обновление документации.
4. Запросите короткий план перед реализацией.
5. Проведите ревью изменений и итеративно уточняйте.

### Что давать агенту на вход

- Структуру проекта (где корневой README, где модули, где тесты).
- Локальные правила (AGENTS.md, CONTRIBUTING.md, style guide).
- Явный контекст версии (язык, фреймворк, окружение).
- Примеры «как правильно» из вашего репозитория.

Практический шаблон постановки задачи:

```text
Цель: добавить раздел X в документацию.
Ограничения: не менять существующие разделы Y, использовать русский язык.
Критерии готовности: обновлены README, проверены внутренние ссылки.
Формат отчёта: summary + список проверок командами.
```

## Скиллы: как конфигурировать и поддерживать

**Скилл** — это повторно используемая инструкция/процедура для агента под узкий тип задач (например: «подготовить релизный changelog», «создать PR по шаблону», «проверить структуру раздела в docs»).

Идея переносима между инструментами; путь установки, metadata, trigger и перечень доступных tools относятся к конкретной поверхности. Каталог ниже — концептуальный шаблон. Для Codex рабочий минимальный вариант показан в лабораторной; не считайте любой файл с названием `SKILL.md` автоматически подключённым.

### Минимальная структура скилла

```text
my-skill/
  SKILL.md
  templates/
  scripts/
  references/
```

Где:
- `SKILL.md` — когда применять скилл, шаги выполнения, ограничения.
- `templates/` — заготовки для повторяемого результата.
- `scripts/` — автоматизация рутинных шагов.
- `references/` — узкоспециализированные справки.

### Правила качественного скилла

- Один скилл — одна цель (без «универсальных комбайнов»).
- Чёткие триггеры: когда использовать, когда не использовать.
- Проверяемый финал: какие артефакты и проверки должны появиться.
- Минимум неоднозначности в формулировках.
- Версионирование: фиксируйте изменения скилла в истории репозитория.

## MCP: зачем нужен и как подключать

**MCP (Model Context Protocol)** стандартизирует обмен с источниками контекста и инструментами: ресурсами, базами, API, системами задач. Авторизация, sandbox и право выполнять конкретный эффект обеспечиваются клиентом, сервером и окружением; протокол сам по себе их не заменяет. Содержимое ресурса — входные данные, а не новое разрешение выполнять инструкции из этого содержимого.

Типовая ценность MCP:
- меньше копипаста в промпт;
- доступ к «живым» данным вместо устаревших сниппетов;
- контролируемые интеграции через серверы MCP.

Базовый процесс подключения:
1. Поднимите/подключите MCP-сервер для нужной системы (например, Git, issue-tracker, docs).
2. Опишите ресурсы и шаблоны ресурсов, которые агент может читать.
3. Ограничьте область доступа по принципу минимальных привилегий.
4. Протестируйте сценарий чтения контекста и выполнения одной безопасной операции.

## CLI-подход: когда удобнее терминал, а не чат

Работа через CLI особенно эффективна, когда нужно:
- выполнить последовательность команд в репозитории;
- быстро проверить состояние (тесты, линтеры, git diff);
- получить воспроизводимый лог действий.

Примеры полезных команд:

```bash
# Перечислить файлы репозитория
rg --files

# Проверить изменения относительно индекса
git diff --name-only

# Посмотреть краткий статус репозитория
git status --short

# Найти ссылки на конкретный документ
rg "01-работа-с-агентами"
```

## Лабораторная: локальный skill и MCP в Codex CLI

**Результат:** агент по явно вызванному skill читает синтетический товар через единственный read-only MCP tool и возвращает цену; файлы проекта не редактируются. Это лабораторная **локального Codex CLI**, не инструкция для Codex cloud, ChatGPT web или обычного OpenAI API. Для offline части нужны только Python 3.12+ и checkout репозитория; модель и аккаунт не нужны. Клиентский шаг требует установленного/авторизованного CLI и может расходовать его обычную квоту.

### Шаг 1: проверить сервер без модели

Из корня репозитория:

```bash
python3 examples/ai-agents/demo_mcp.py --self-test
```

Ожидается одна строка `PASS: initialization, tools/resources, immutable fixture, invalid input, notification silence, stdio framing`. [Исходник сервера](../examples/ai-agents/demo_mcp.py) использует стандартную библиотеку, **stdio transport** и UTF-8 JSON-RPC: одно сообщение на строку, никаких баннеров в stdout. Поддержаны initialize → initialized, ping, tools/list/call, resources/list/read и пустой список resource templates. Версия протокола сервера — `2025-11-25`; несовместимый клиент должен завершить соединение.

Фиксированный ресурс `demo://catalog/sku-001` и tool `get_demo_item` возвращают только `sku-001`, имя, `priceMinor=99000`, `currency=RUB`. Произвольные URI, пути, команды и доступ в сеть не реализованы. `readOnlyHint` — метаданные для клиента; реальная граница примера обеспечивается отсутствием операций записи в коде сервера. Это ограниченный учебный сервер без subscriptions, auth и production hardening.

### Шаг 2: создать skill в учебном каталоге

Не меняем глобальную конфигурацию или пользовательские skills. Следующие команды создают отдельную заготовку в `work/agent-lab/`:

```bash
mkdir -p work/agent-lab/.agents/skills/catalog-review
cat > work/agent-lab/.agents/skills/catalog-review/SKILL.md <<'SKILL'
---
name: catalog-review
description: Читает синтетический товар sku-001 через учебный MCP tool get_demo_item. Не применять для реальных каталогов, записи данных или работы с произвольными файлами.
---

1. Найди tool get_demo_item сервера demo; если его нет, сообщи о недоступности и останови упражнение.
2. Вызови его с аргументами {"sku":"sku-001"}; не подменяй вызов чтением исходника или выдуманным ответом.
3. Верни SKU, priceMinor и currency, затем сумму в основных единицах: для RUB minor / 100.
4. Укажи имя вызванного tool. Не меняй файлы, не вызывай сеть или другие системы.
SKILL
```

Для этой поверхности metadata `name` и `description` обязательны; repo-local discovery использует `.agents/skills` от текущего каталога до корня репозитория. Instructions в `SKILL.md` описывают процесс, но не выдают дополнительные права. Файл оставляем внутри временной лабораторной, а не добавляем как новую учебную страницу сайта.

### Шаг 3: запустить CLI с временным MCP override

Из корня репозитория вычислите JSON/TOML-массив абсолютного пути и передайте настройки только текущему процессу. Shell-подстановка возвращает путь, а не credentials:

```bash
lab_mcp_args="$(python3 -c 'import json; from pathlib import Path; print(json.dumps([str(Path("examples/ai-agents/demo_mcp.py").resolve())]))')"
codex -C work/agent-lab --sandbox read-only \
  -c 'mcp_servers.demo.command="python3"' \
  -c "mcp_servers.demo.args=$lab_mcp_args" \
  -c 'mcp_servers.demo.enabled_tools=["get_demo_item"]'
```

В CLI откройте `/mcp`: сервер `demo` должен быть активен. Через `/skills` или `$` выберите `catalog-review` и передайте запрос:

```text
$catalog-review Проверь цену sku-001 через учебный MCP tool.
```

Ожидаемые поля ответа: `sku-001`, `priceMinor=99000`, `currency=RUB`, `990.00 RUB`; имя tool содержит `get_demo_item` (клиент может добавить namespace). В истории должен быть реальный вызов с `{"sku":"sku-001"}`, а diff файлов отсутствует. Одно совпадение текста без tool-call не считается успешным прохождением. Ресурс можно проверить offline self-test; применение ресурса и tool — разные MCP операции.

### Приёмка и диагностика

| Проверка | Ожидаемый результат |
|----------|---------------------|
| Offline self-test | Инициализация, чтение fixture, ошибки аргументов/URI и отсутствие ответов на notifications проходят без модели |
| Неизвестный SKU | Tool возвращает `isError: true`; агент не выдаёт выдуманную цену |
| Лишний аргумент `path` или произвольный URI | Сервер отвергает запрос; читать чужие файлы через этот интерфейс невозможно |
| Сервер отсутствует | Skill сообщает о недоступности, не подменяет источник |
| Вызов из CLI | В логе виден `get_demo_item`, значения совпадают с fixture, `git diff` без изменений |

Если `/mcp` не видит сервер, проверьте абсолютный путь, `python3 --version`, stderr и поддержку `-c` текущей версией CLI. Если skill не виден, проверьте текущий каталог, YAML metadata и список `/skills`; после изменения перезапустите CLI. Не считайте успешный self-test доказательством работы discovery или политики конкретного аккаунта: это отдельные клиентские проверки.

## Продуктовая матрица: что именно сравниваем

Бренды целиком несравнимы: один поставщик может одновременно предлагать расширение IDE, локальный CLI-агент, удалённый web-agent и API. Здесь сравниваются конкретные поверхности:

- **GitHub Copilot agent mode** — агент в IDE (VS Code, Visual Studio, JetBrains, Eclipse и Xcode; набор функций различается) и **Copilot coding agent** — web-agent в GitHub, который работает в GitHub Actions-окружении и создаёт pull request. Это не один и тот же продуктовый режим ([IDE agent mode](https://docs.github.com/en/copilot/concepts/agents/about-copilot-agents), [coding agent](https://docs.github.com/en/copilot/concepts/agents/about-copilot-coding-agent)).
- **Claude Code** — агент для репозитория с CLI и интеграциями IDE; здесь не сравнивается обычный чат Claude.ai или Anthropic API ([обзор](https://code.claude.com/docs/en/overview), [IDE integrations](https://code.claude.com/docs/en/ide-integrations)).
- **OpenAI Codex** — локальные Codex CLI и IDE extension, а также облачный web-agent Codex cloud. OpenAI API и Codex SDK — отдельные программные поверхности и в матрицу не включены ([CLI](https://developers.openai.com/codex/cli), [IDE extension](https://developers.openai.com/codex/ide), [cloud](https://developers.openai.com/codex/cloud)).

### Сравнение проверяемых функций

| Поверхность | Работа с репозиторием и terminal tools | MCP | Approval model | Custom instructions | Среда |
|---|---|---|---|---|---|
| **GitHub Copilot agent mode (IDE)** | Ищет контекст, правит файлы, предлагает и запускает terminal tools в workspace | Да; поддержка и настройка зависят от IDE ([MCP](https://docs.github.com/en/copilot/customizing-copilot/extending-copilot-chat-with-mcp)) | Опасные tools/команды требуют подтверждения; доверие можно настраивать | `.github/copilot-instructions.md`, path-specific instructions и instruction files ([документация](https://docs.github.com/en/copilot/customizing-copilot/adding-repository-custom-instructions-for-github-copilot)) | Локальная IDE и её terminal; точную матрицу IDE нужно сверять |
| **GitHub Copilot coding agent (web-agent)** | Клонирует репозиторий, меняет код, запускает commands и открывает PR | Да, но для coding agent есть отдельная конфигурация и allowlist tools ([MCP](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/extend-coding-agent-with-mcp)) | Агент ограничен GitHub Actions-окружением; результат проходит обычный PR review, а workflow из PR не запускаются без одобрения | Репозиторные Copilot instructions и custom agents | Удалённая GitHub Actions-среда; её можно настроить ([environment](https://docs.github.com/en/copilot/how-tos/use-copilot-agents/coding-agent/customize-the-agent-environment)) |
| **Claude Code (CLI / IDE)** | Читает кодовую базу, правит файлы, запускает shell commands и работает с Git | Да: local, project и user-scoped servers ([MCP](https://code.claude.com/docs/en/mcp)) | Правила allow/ask/deny, permission modes и sandbox для shell/filesystem/network ([permissions](https://code.claude.com/docs/en/permissions), [sandboxing](https://code.claude.com/docs/en/sandboxing)) | `CLAUDE.md`, `.claude/rules/`, settings и hooks ([memory](https://code.claude.com/docs/en/memory)) | Terminal на macOS, Linux и Windows; интеграции VS Code-family и JetBrains |
| **OpenAI Codex (CLI / IDE extension)** | Инспектирует репозиторий, правит файлы и запускает shell tools | Да; MCP servers задаются в общей конфигурации CLI и IDE ([MCP](https://developers.openai.com/codex/mcp)) | Сочетание sandbox и approval policy для записи вне workspace, сети и команд ([security](https://developers.openai.com/codex/security)) | Иерархия `AGENTS.md`, плюс config и skills ([AGENTS.md](https://developers.openai.com/codex/guides/agents-md)) | CLI: macOS/Linux, Windows имеет особые условия; extension для VS Code-family IDE |
| **OpenAI Codex cloud (web-agent)** | Работает с подключённым GitHub-репозиторием в изолированном облачном окружении; возвращает diff/PR | Не следует переносить возможности local MCP на cloud без проверки документации | Изолированное environment; доступ к сети во время agent phase отдельно контролируется | `AGENTS.md` и environment setup scripts | Облачный Linux container ([cloud environments](https://developers.openai.com/codex/cloud/environments)) |

> Пустая или ограниченная ячейка не означает, что поставщик в целом не имеет функции: она может быть доступна в другой поверхности. Например, MCP в локальном CLI не доказывает его наличие в web-agent.

### Что перепроверить перед выбором

> **Тарифы, rate limits и квоты, лимиты контекста, доступные модели, региональная доступность и функции конкретного тарифа изменчивы.** Не используйте эту матрицу как прайс-лист: перед покупкой повторно сверьте официальные страницы [GitHub Copilot plans](https://docs.github.com/en/copilot/get-started/plans-for-github-copilot), [Claude Code costs](https://code.claude.com/docs/en/costs) и [Codex pricing](https://developers.openai.com/codex/pricing).

Также уточните у администратора организации: разрешена ли нужная модель, можно ли подключать MCP, доступен ли web-agent для данного репозитория и какие политики data retention используются.

## Чек-лист собственной оценки

Возьмите одинаковую небольшую задачу: исправить дефект в двух-трёх файлах, добавить тест и обновить краткую документацию. Для каждого инструмента зафиксируйте:

- [ ] Увидел ли агент корневые и вложенные custom instructions и соблюл ли границы задачи?
- [ ] Нашёл ли он связанный код и тесты без ручного перечисления всех файлов?
- [ ] Запросил ли approval перед опасной командой, доступом к сети или выходом за workspace?
- [ ] Запустил ли нужные тесты/линтеры и точно ли отчитался об ошибках?
- [ ] Остался ли diff минимальным, понятным и без посторонних изменений?
- [ ] Можно ли воспроизвести результат из лога, а время, число итераций и стоимость приемлемы?

Сравнивайте не впечатление от одного ответа, а долю успешных повторов на нескольких сопоставимых задачах.

## Типичные ошибки и как их избежать

- Ошибка: «Сделай хорошо» без критериев.
  - Решение: задавайте DoD (Definition of Done) в явном виде.
- Ошибка: отсутствие локальных правил проекта.
  - Решение: перед запуском задачи передайте AGENTS/README/стайлгайды.
- Ошибка: попытка одним промптом решить слишком большую задачу.
  - Решение: дробите на этапы и фиксируйте результат каждого шага.
- Ошибка: слепое принятие результата агента.
  - Решение: обязательный code review и запуск проверок.
